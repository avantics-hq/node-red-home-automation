home-cover-group1 input · 1 + one output per memberhome automation

Several covers. One honest answer.

Moves several covers as one, such as the left and right of a curtain: one request goes to every member, each under its own request ID, and the group reports how far it got. In the palette it is home-cover-group; on the canvas it shows its name, or “<area> cover group”, or “cover group”.

A cover group has no MQTT topics or Home Assistant entity of its own: Home Assistant can group the covers’ entities itself.

Looking for wiring?

Follow Wire a cover, and see the Cover pair example for a group of two.

Inputs

Requests and member answers share the same input.

Input properties
PropertyTypeMeaning
msg.payloadstring / numberA cover request: "open", "close", "stop", a position or a preset name. Each member gets the same request.
msg.stopIfMovingbooleanPassed on to each member, as for a cover controller.
msg.respectManualbooleanPassed on to each member, as for a cover controller.
msg.theatreobjectA member’s result: wire each member cover controller’s second output back into the group. Other state from a cover controller, and its moving signal, are ignored.

Outputs

Output 1 is the group’s result, then one output per member in the order of Members, each labelled with its name. Changing Members changes the number of outputs, and the editor moves each member’s wire with its name.

Output ports
PortMessageConnect to
1 · Group resultmsg.theatre = {kind: "target_state", target: "cover", status, details}Debug, or another result consumer.
2 and on · One per memberThat member’s request, with its own coverRequestId and msg.topic naming the member.That member’s cover controller input. No switch node is needed.
  • ready only when every member confirms.
  • Once every member has settled with any not ready, failed with reason partial (some confirmed) or none-confirmed, and details.members saying what each did.
  • A member silent at the Answer deadline counts as no-answer.
  • A new request first answers the open one failed with reason superseded.

A cover controller answers the request even when it doesn’t carry it out, with the reason.

Settings

Defaults below are from the editor definition. The deadline is in seconds.

Editor settings and exact defaults
Setting / propertyDefaultMeaning
Namename · stringEmptyDisplay label.
Areaarea · stringEmptyOptional; labels the node and its traces.
Membersmembers · JSON array["left","right"]At least two unique names, each lowercase, starting with a letter, with letters, digits, _ or -. Each name gets its own output.
Answer deadline (s)deadlineSeconds · number120How long members have to answer before a silent one counts as no-answer. At least 1.

The hidden outputs key is internal: the editor keeps the output count (default 3) and a map of how each member’s port moved when Members changes, as the core switch node does. It is not an editor setting.

Status

The node status shows idle before the first request, then <ready>/<members> confirmed: green when every member is ready, blue otherwise.
