Before you wire it

A scene (home-scene) takes some of a room’s lights for a while. It holds each on or off with the values you give it, and pauses motion lighting, so motion doesn’t switch the bath lights off or the exercise light back on. When it ends, each room gives its lights back what they were before the scene.

  • You need a room lighting controller for the room, with each light and socket in its Targets JSON. A socket is a target marked "onOffOnly": true, through its own adapter.
  • To pause motion lighting, a motion lighting policy wired into that room.
  • To start and stop it from Home Assistant, an MQTT broker node, as for the other publishing nodes (see Home Assistant).

Wire a scene

Import Scene from the examples (Import → Examples → @avantics/node-red-home-automation), or add a scene node from the palette.

  1. Name it.

    The name is how its rooms, its motion policies and Home Assistant know it, so give each scene its own: Exercise mode, Bath.

  2. List its lights.

    One entry per light or socket, by its id in the room’s Targets JSON:

    Exercise mode · main light off, TV socket on
    [{"target": "main", "state": "OFF"},
 {"target": "tv", "state": "ON"}]
    Bath · two lights dimmed warm
    [{"target": "ceiling", "state": "ON", "brightnessPct": 30, "colorTempKelvin": 2700},
 {"target": "mirror", "state": "ON", "brightnessPct": 50}]

    Brightness is 0-100 % and colour temperature in kelvin; a light given neither just switches on. A scene with no lights only pauses motion.

  3. Set its safety timer.

    It ends itself after 4 hours by default, so a scene left on doesn’t hold the room overnight. 0 turns the timer off.

  4. Start and end it.

    Send msg.scene = {kind: "start"} and msg.scene = {kind: "end"} from your flow, or use its Home Assistant switch (below).

End it when something happens

A scene can end on a condition, such as the trainer’s power falling, the bath lights being switched off or a door opening. The condition lives in your flow: when it is met, send the scene an end, with what ended it.

Change node · after a switch node passing power below 20 W
msg.scene = {kind: "end", by: "trainer off"};

The scene shows off · ended by trainer off. An end while it is off does nothing, so a condition that stays true can keep sending it. The example flow builds this from a switch node and a change node.

What happens when it ends

Each room gives each light back what it was when the scene took it:

  • A light the room was running is the room’s again, on or off as it was, in the room’s style as it is now: a bath from 20:00 to 21:30 gets the 21:30 style, not 20:00’s.
  • A light that was off goes off.
  • A light a person had set gets their brightness and colour back, and stays theirs.
  • A light a person changed during the scene is theirs: the scene’s end leaves it alone.

Motion lighting resumes when its pause lifts. With the room vacant, motion switches lights off as it normally would.

Two scenes at once

Scenes stack. If Bath starts while Exercise mode holds the same light, Bath takes it; when Bath ends, the light goes back to what Exercise mode asked for, not to the room. If Exercise mode ends first, the light stays with Bath, and goes back to the room when Bath ends. Lights only one scene holds follow that scene. Each scene pauses motion under its own name, so motion resumes only when both have ended.

Start and stop it from Home Assistant

  1. Switch publishing on.

    Give the scene an area, and switch on Publish state over MQTT and Home Assistant discovery. Wire output 3 to an MQTT out node.

  2. Wire its set topic back in.

    An MQTT in node on home/<area>/scene/<name>/set into the scene, where <name> is its name in lower case with other characters as _ (exercise_mode).

Home Assistant then shows a switch for the scene: on while it is on, off once it ends by any route. Switching it off ends the scene “by home-assistant”.

Restarts and deploys

A scene keeps its state in its node context, which lasts across restarts and full deploys only with a context store (see Install). With one, a scene that was on is still on, with its timer; if the timer ran out meanwhile, the scene ends as the flows start. Without one, the scene and its rooms both start with nothing saved: the scene is off, and the rooms no longer know it held their lights, so the lights stay as they are until something changes them.

Deleting a scene while it is on lets its lights and motion go, when you deploy with “Modified nodes” or “Modified flows”.
