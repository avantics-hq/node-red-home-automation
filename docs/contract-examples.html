Contract examples

Seven deterministic examples call the same pure reducers used by the Node-RED adapters. Synthetic configuration keeps transport ownership visible.

Contract examples

Each example declares configuration, applies deterministic inputs, asserts one consumer-visible invariant and returns its commands or outputs as JSON.

Occupancy fusion

Sensor policy

Motion establishes occupancy. Optional presence can hold it after motion clears, but cannot establish it alone.

Contract
presence:on  → no output
motion:on    → occupied:true
motion:off   → held
presence:off → occupied:false

Occupancy to lighting intent

Motion policy

Dark, enabled occupancy produces semantic intent; it does not publish a device command.

Contract
{ occupied: true, trigger: "motion" }
→
{ kind: "intent", state: "ON",
  targets: ["ceiling", "worktop"] }

Explicit manual brightness

Switch policy

A classified double action becomes one full-brightness intent with manual ownership.

Contract
{ action: "double" }
→
{ state: "ON", manual: true,
  values: { brightnessPct: 100 } }

Room lighting boundary

Command owner

The room controller converts semantic lighting intent into the sole transport command and records its policy source.

Contract
{ kind: "intent", state: "ON",
  source: "motion" }
→
{ topic: "demo/lighting/ceiling/set",
  lighting_command: { source: "motion" } }

Media-source evidence

Readiness policy

Command success enters confirmation. Fresh active-application evidence is what satisfies application readiness.

Contract
activate → command_result:ok → confirming
observed:{ active, application, paused }
→ ready

Bounded receiver volume

Command ownership

Rapid relative requests accumulate against one target. Fresh confirmation releases ownership so later external adjustment becomes the baseline.

Contract
relative:+1 → MV31
relative:+1 → MV32
observed MV32 → ready · released
observed MV28 → −52 dB, the external baseline

Theatre activity

Coordination

One activity request fans out semantic target intents and reaches ready only from fresh mandatory evidence.

Contract
movie_night request
→ display · receiver · source · lighting · backlighting
→ fresh target evidence
→ { phase: "ready", availability: "available" }

Run the contracts

The aggregate command compiles the package, executes all seven examples and fails if an asserted invariant changes.

Terminal
npm ci
npm run examples

What the examples preserve

  • Policy before transport

    Sensor and user events become semantic outcomes before a target owner selects a protocol.

  • Evidence before ready

    Command acceptance never substitutes for a fresh observation of the required state.

  • Finite state

    Timers, retries, generations and traces remain bounded and stale work stays inert.

Privacy boundary

Every identifier, topic, profile, timestamp and coordinate in these examples is synthetic. The examples contain no device inventory, addresses, credentials, entity identifiers, flow exports or operational records.
