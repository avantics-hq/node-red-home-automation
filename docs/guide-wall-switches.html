Guides / Wall switches

Wire wall switches

Turn wall switch flips and button presses into lighting requests through the switch lighting policy node. A single press toggles the room’s lights; a double press sets them to full brightness and marks them as set by a person.

Before you wire it

This guide adds a wall switch or button to a room that already has a room lighting controller (home-room-lighting-controller). The switch goes to its own node, the switch lighting policy (home-switch-lighting-policy, shown on the canvas as switch policy). It turns what the switch reports into msg.lighting intents for the room controller. It knows nothing about occupancy or motion.

Every message names its kind in msg.source. The policy accepts three kinds:

Switch messages the policy accepts
msg.sourcemsg.payloadUse it for
"switch"{state: true} or {state: false}A wall switch that reports its position (raw edges). The state must be a boolean; anything else is ignored.
"switch-action""single" or "double", or an object with that actionA button that already reports which press it saw (pre-classified actions). Case does not matter.
"switch-availability"true, "online", "available" or "on"; false, "offline", "unavailable" or "off"Whether the switch device is reachable.

A raw switch report can carry the time it was observed in msg.observedAt or payload.observedAt. Without one, the policy uses the time the message arrived; a retained report without one has no time, so the status shows stale with age ?.

The policy commands nothing itself. The room controller sends the light commands, straight to the lights over MQTT. Home Assistant is not in this path.

Wire the switch to the room

One switch policy feeds one room controller. Convert your switch’s reports into one of the messages above on the way in.

Connections
FromConnect toWhy
Switch reports, convertedswitch policy inputmsg.source = "switch" with a boolean state, or "switch-action" with the press.
Switch availability, convertedswitch policy inputmsg.source = "switch-availability", so the policy knows when the switch is offline.
switch policy outputRoom lighting controller inputThe policy’s only output carries the msg.lighting intents.
Room lighting controller outputMQTT outWire the commands unchanged: the controller tells its own commands from other people’s by watching each light’s command topic.

A raw switch needs its report turned into a boolean. In a Function node between MQTT in and the policy:

Function → switch policy · raw switch report
msg.source = "switch";
msg.payload = {state: msg.payload.state === "<your device’s on value>"};
return msg;

A button whose message already has an action of single or double needs only the source set:

Function → switch policy · pre-classified button
msg.source = "switch-action";
return msg;
  1. Match the targets.

    Set the policy’s Targets to the ids of the room controller targets the switch controls. The default is ["main"].

  2. Keep the window short.

    Leave Raw-edge window ms at 500 unless two quick flips are not being seen as a double press.

  3. Try it without a switch.

    The Room lighting example has a “wall switch edge” Inject node that sends msg.source = "switch" with {"state":true} into a switch policy wired to a room controller.

What each press requests

With raw edges, the policy times changes of the switch’s state. A change starts the raw-edge window. A second change inside it is a double press; when the window ends with no second change, it is a single press. A report that repeats the current state is not a press.

Presses and requests
PressRaw switchPre-classified actionIntent sent
SingleOne change, no second within the window"single"state: "TOGGLE"
DoubleTwo changes within the window"double"state: "ON", manual: true, values: {brightnessPct: 100}
Anything else, such as a hold—Other actionsNothing; traced as unsupported-action

Every intent names the policy’s targets and carries source: "wall" and person: true. A double action on the default target sends:

switch policy → room lighting controller · double press
msg.lighting = {
  kind: "intent",
  targets: ["main"],
  state: "ON",
  source: "wall",
  person: true,
  manual: true,
  values: {brightnessPct: 100}
};

The room controller resolves TOGGLE per light: off if it last set or saw the light on, otherwise on. A light switched on by a single press gets circadian styling when circadian lighting is on and the light is under the room’s control.

A pre-classified action cancels a raw press still waiting for its window to end.

Presses, motion and manual lights

Because every press carries person: true, the room controller treats it as a person’s choice:

  • Motion keeps its hands off. The motion policy’s vacancy OFF carries vacantSince. The room controller ignores it for a light a person set after the room went vacant (traced as person-set-after-vacancy).
  • Presses reach held lights. A light held by an owner, such as an activity, ignores owner-less intents like motion, but a press still reaches it.
  • A double press makes the light manual. Circadian refresh then leaves it alone. Enabling circadian lighting returns manual lights to the room’s control.
  • Switching off hands the light back. A light switched off by a person or its owner returns to in-control.
Switches don’t go to the motion policy.

Switch messages sent to the motion lighting policy are ignored. Wire switches only to the switch policy.

Retained reports and restarts

The policy keeps the switch’s last known state (its baseline) in the node’s context, so a flip after a restart is still measured against it.

  • Retained reports are not presses. A raw report with msg.retain = true only re-baselines the state. A retained switch-action is ignored.
  • Mark a first read and polled snapshots. Set msg.baseline = true on a report you asked the device for, so it updates the baseline without counting as a press.
  • With no baseline, the first report is a press. On a policy that does not yet know the switch’s state, the first report that is neither retained nor marked baseline counts as a change and sends a single-press TOGGLE. Mark a first read with msg.baseline = true.
  • Offline means start again. After the switch reports unavailable, its first report when it returns re-baselines instead of counting as a press.

Node context is kept in memory unless you set up a context store, so a restart or redeploy clears the baseline, and the room controller forgets which lights a person set. See Recommended setup: a file context store.

Stop or open a cover from a button

The switch policy only makes lighting intents. To make a button stop a moving cover, or open it otherwise, send its request to the cover controller with msg.stopIfMoving = true. See Leave a person’s move alone in the covers guide.

Check the result

The policy’s status shows how much it trusts what it knows about the switch.

Read the status
What you seeWhat it means
switch fresh · <age>The switch reported within the freshness time.
switch stale · <age>The last report is older than the freshness time, has no usable timestamp (shown as age ?), or came before the flows started and nothing has confirmed it since.
awaiting switch baselineThe policy does not yet know the switch’s state.
switch unavailableThe switch was reported unavailable.

Connect a Debug node to the policy’s output and press the switch: a single press shows a TOGGLE intent; a double press shows the full-brightness ON intent. Then check the room controller’s commands reach the light.
