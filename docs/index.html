Target architecture

Inputs

HA dashboard, wall controls, schedules and policies emit activity requests.

Activity owner

One pure reducer owns desired activity, generation, phase and failure.

Target owners

Display, AVR, source, lighting and backlighting controllers own their state.

Transports

Bravia REST, Denon TCP, Shelly RPC, MQTT and explicit HA fallbacks.

State surfaces

MQTT state, HA status, notifications, metrics and recovery evidence.

Control surfaces request activities. They never become device owners or infer activities from entity changes.

Design rules

One owner per target

No duplicate power, source, screen, lighting or fallback command path.

Pure domain logic

Reducers under lib/ contain no Node-RED, network or timer dependencies.

Thin wrappers

Nodes translate messages, persist context and schedule generation-safe work.

Semantic adapters

Transport details stay behind query, command and observation contracts.

Target-state commands

Use on, standby, input and position—not blind toggles or inferred intent.

Latest request wins

Every delayed action and response carries its generation and rejects stale work.

Observed completion

An activity is ready only after all mandatory postconditions are fresh and true.

Clean cutover

Migrate all callers, then remove aliases, fixed delays and obsolete command paths.

Source-control and release model

1. Build

Test and pack the module from node-red-home-automation.

2. Validate

Compare the candidate graph with the live Node-RED project and reject unrelated drift.

3. Deploy

Create matching backups, install package and flow, restart and smoke the live surface.

4. Record

Commit all repositories and record package version, package SHA, infrastructure SHA and flow SHA.

RepositoryOwnsMust not own
node-red-home-automationReducers, adapters, nodes and testsDeployment credentials, live flows or infrastructure operations

Keep package, infrastructure and live-flow ownership separate until the activity contract is stable.

Extension backlog enabled by this design

Whole-home audio

Activity profiles

Restore last source and vary lighting without duplicating control graphs.

Manual drift

Classify physical remote changes without silently changing desired activity.

Operational metrics

Latency, retries, fallbacks, stale cancellations and adapter availability.

Degraded operation

Visible optional-component failures while mandatory safety remains enforced.

Broader smart-home backlog

Tracked here for visibility; explicitly outside the theatre-controller scope.

Shelly local lighting failover

Inventory and version the scripts on light-owning Shelly devices, then prove wall inputs still switch the intended relays while MQTT is unavailable. Test broker loss, Shelly reboot while offline, broker recovery, state reconciliation and duplicate-command suppression before rollout.

Fixed decisions and safety constraints

  • Node-RED owns intent and sequencing; Home Assistant is a control and status surface.
  • Never cut mains power to the OLED TV or projector as part of normal activity control.
  • HDMI-CEC may remain for physical remote convenience but is not authoritative state.
  • Projector shutdown and screen closure remain ordered by measured power and cool-down state.
  • Credentials remain in Node-RED's encrypted credential store and never enter flow JSON, logs or this document.
  • Live steps that can power or move equipment require an explicit maintenance window.
