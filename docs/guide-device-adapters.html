Guides

Connect a device

A device adapter sits between one device and its controller. It turns the device’s own MQTT messages into the controller’s neutral readings, and the controller’s neutral commands into messages the device understands.

Before you wire it

The cover controller (home-cover-controller) is device-neutral. It sends commands as msg.cover_command = {operation, position, requestId, generation, attempt}, where operation is set_position, stop or observe (read the cover now). An Open, close and stop only cover sends open, close, stop or observe. It expects readings back as msg.cover = {kind: "observed", …} and {kind: "availability", online}.

An adapter does the translation for one kind of device, so the controller never needs to know which device it drives. An adapter has no broker connection of its own: device messages arrive from an MQTT in node, and its publications leave through an MQTT out node.

  • Pick the adapter for your device: the shelly cover node (home-shelly-cover) or the zigbee2mqtt cover node (home-z2m-cover).
  • Have a broker connection in Node-RED that both the MQTT in and MQTT out nodes use.
  • Both adapters speak the device’s own MQTT messages, with no function nodes. Neither commands the device through Home Assistant.

Both adapters report 0 = closed and 100 = open. If your device runs the other way, set Invert positions on the controller.

Wire either adapter the same way

Both adapters have one input and two outputs. Output 1 goes to the device; output 2 goes to the cover controller.

Four connections for either adapter
FromConnect toWhy
MQTT in (output: auto-detect)Adapter inputThe device’s reports and availability.
Controller output 1Adapter inputNeutral device commands.
Adapter output 1MQTT outSame broker; leave the MQTT out topic empty, because each message carries its own topic.
Adapter output 2Controller inputReadings and availability for the controller.

Anything else that reaches an adapter’s input is ignored.

Wire a shelly cover

The shelly cover node connects a Gen2-or-later relay device in cover mode, over the device’s own MQTT API. The covers guide walks through its full wiring; this is the summary.

shelly cover settings
SettingDefaultWhat to set
MQTT topic prefixNone: requiredThe device’s topic prefix: its device ID unless a custom prefix is set on the device. It cannot contain + or #.
Cover ID00, or 1 for a device’s second cover.
  1. Prepare the device.

    Calibrate the cover on the device. Turn MQTT on with Enable MQTT Control (the default); without it the device ignores the commands. Keep RPC status notifications on (also the default) so each change is reported.

  2. Subscribe to the whole prefix.

    One MQTT in node on <prefix>/# feeds the adapter. It reads <prefix>/status/cover:<id>, change notifications on <prefix>/events/rpc, and availability on <prefix>/online.

  3. Keep the controller as a position cover.

    Leave Cover as “Takes a position (0 to 100)”. The adapter translates set_position, stop and observe; it does not translate the open and close commands of an Open, close and stop only cover.

No position, no guess.

A cover that is not calibrated, or does not know its position, has no position to report. The controller’s command in hand fails with reason not-calibrated or position-unknown, and no position is sent to an uncalibrated cover.

Wire a zigbee2mqtt cover

The zigbee2mqtt cover node connects a Zigbee2MQTT cover (a blind, shutter or curtain motor) over Zigbee2MQTT’s MQTT messages.

zigbee2mqtt cover settings
SettingDefaultWhat to set
Base topiczigbee2mqttZigbee2MQTT’s base topic, unless you changed it in Zigbee2MQTT’s settings.
Friendly nameNone: requiredThe device’s friendly name in Zigbee2MQTT (or its IEEE address if it has none).

Neither setting can contain + or #. With no Name, the node is labelled with the friendly name.

zigbee2mqtt cover topics
TopicDirectionCarries
<base>/<friendly name>MQTT in → adapterThe device’s whole state as JSON.
<base>/<friendly name>/availabilityMQTT in → adapterOnline or offline.
<base>/<friendly name>/setAdapter → MQTT outPosition and open, close or stop commands.
<base>/<friendly name>/getAdapter → MQTT outA request for a fresh reading.
  1. Add two MQTT in nodes.

    Subscribe one to <base>/<friendly name> and another to <base>/<friendly name>/availability, both with output auto-detect, and wire both to the adapter.

  2. Turn on availability in Zigbee2MQTT.

    Availability needs Zigbee2MQTT’s availability setting. Without it, the cover is taken as available. The adapter accepts {"state": "online"} or {"state": "offline"}, or plain online or offline, and turns it into {kind: "availability", online}.

  3. Choose the controller’s cover type.

    See which cover type fits below.

The adapter reads each state report like this:

  • Position comes from position, 0 closed and 100 open as Zigbee2MQTT reports by default. If yours runs the other way, set Invert positions on the controller, or the device’s invert_cover option.
  • Motion comes from motor_state (opening, closing, stopped; pause reads as stopped), from moving (UP, DOWN, STOP), or from running when it is false (stopped). A cover that reports no motion is confirmed by the controller’s Settle time.
  • End state, for a cover with no position, comes from Zigbee2MQTT’s OPEN or CLOSE, but only once its motion says it has stopped: before that, the state can show where it is going rather than where it is.
  • Time: observedAt is when the report arrived, never a time the device gives.
  • Battery and charging status are passed on as reported facts; the controller never acts on them.

Choose the controller’s cover type

The controller’s Cover setting must match what the device reports.

Which cover type fits
The deviceSet Cover toHow a move is confirmed
Reports a position (any shelly cover; a zigbee2mqtt cover that reports position)Takes a position (0 to 100)A stopped report at the target, or the same position for the settle time.
Reports no position (a zigbee2mqtt cover with only OPEN / CLOSE)Open, close and stop onlyA reported end state, or a move that ran for its Full travel time. With no motion reports either, it cannot be confirmed, and the controller says so.

If a position cover receives a reading with no position, the controller’s error says: “observed cover reading has no position: for a cover that reports none, set the cover node’s Cover to "Open, close and stop only"”.

What each adapter sends

You send requests such as "open", 60 or "stop" to the controller, as in the covers guide. The controller turns them into neutral commands, and the adapter sends these:

Neutral command to device message
Controller commandshelly cover, on <prefix>/command/cover:<id>zigbee2mqtt cover
set_positionpos,<0-100>{"position": <0-100>} on …/set
openNot translated{"state": "OPEN"} on …/set
closeNot translated{"state": "CLOSE"} on …/set
stopstop{"state": "STOP"} on …/set
observestatus_update: the device reports a fresh status{"position": ""} on …/get, or {"state": ""} for a cover with no position

Some Zigbee2MQTT devices cannot be read through …/get; they still report their position whenever it changes.

Inject → cover controller · read the cover again (a Status node watching MQTT out does this each time it connects)
msg.cover = {kind: "startup"};
return msg;

On startup the controller reads the cover again rather than trusting old state, so the adapter sends its observe message.

Wire a shelly switch

The shelly switch node connects one switch channel of a Gen2-or-later relay, over the device’s own MQTT API, used the way the device is set up. It reads the device’s configuration for its channel at startup and whenever the device comes online, and shows what it found in its status.

shelly switch settings
SettingDefaultWhat to set
MQTT topic prefixNone: requiredThe device’s topic prefix: its device ID unless a custom prefix is set on the device. It cannot contain + or #.
Switch ID00, or the number of another switch on a device with more than one. Use one node per switch.
ModeAs the device is set upLeave it to read the device’s own configuration, or set detached or relay to override it. Set it when the configuration can’t be read.
  1. Subscribe to the whole prefix.

    One MQTT in node on <prefix>/# feeds the adapter, and its first output goes to an MQTT out node with no topic set. The configuration request’s reply is addressed under the same prefix, so nothing more is needed.

  2. Detached: the switch drives the room.

    The relay stays on to power smart bulbs. Wire the adapter’s second output to a switch lighting policy: a toggle switch’s flips become edges, with the device’s status as the baseline, and a push button’s single, double or long presses become actions (the switch policy acts on single and double; long is passed on for later use). The relay is never commanded, and a relay that reports off is flagged in the status: the bulbs have lost power.

  3. Any other mode: the relay is the light.

    The adapter reports the relay’s on/off state, with whether a person changed it at the switch, and takes on and off. No node of this package reads that state yet.

No configuration, no guess.

If the device doesn’t answer within 10 seconds, the status says configuration unreadable: set Mode, and nothing is passed on until the Mode setting says how.

Wire a zigbee2mqtt light

The zigbee2mqtt light node connects one Zigbee2MQTT light, or a Zigbee2MQTT group, to a room lighting controller: the room’s neutral commands become Zigbee2MQTT’s /set messages, exactly as the room sent them before 6.0, and the light’s reports become readings. Use one per light in the room’s Targets JSON.

zigbee2mqtt light settings
SettingDefaultWhat to set
TargetNone: requiredThe light’s id in the room’s Targets JSON.
Base topiczigbee2mqttZigbee2MQTT’s base topic.
Friendly nameNone: requiredThe light’s or group’s name in Zigbee2MQTT.
Zigbee2MQTT groupOffOn for a group.
  1. Subscribe to the light’s topics.

    One MQTT in node on zigbee2mqtt/<device>/# (output: auto-detect) feeds the adapter: the light’s state, its /set topic (to see other people’s commands) and its availability.

  2. Wire it to the room both ways.

    The room’s second output (light commands) into the adapter; the adapter’s second output (readings) back into the room. One wire from the room can feed every light’s adapter.

  3. Send its messages out.

    The adapter’s first output to an MQTT out node with no topic set.

A group takes the same commands; Zigbee2MQTT works out its state from what it sent and its members’ reports. A group has no availability and can’t be asked to report. Each light’s availability is shown on its control state and in the room’s status, and changes nothing. A 5.x room’s dialog can create these nodes for its old targets: see the room controller. Full reference: Zigbee2MQTT light.

Choose an adapter

shelly cover

A Gen2-or-later relay device in cover mode, calibrated on the device. Position covers only. One MQTT in node on <prefix>/#.

zigbee2mqtt cover

A Zigbee cover paired with Zigbee2MQTT. Position covers, or open, close and stop only. Two MQTT in nodes: the device topic and its availability.

zigbee2mqtt light

A Zigbee light or group paired with Zigbee2MQTT, for a room lighting controller. One MQTT in node on zigbee2mqtt/<device>/#.

shelly switch

A Gen2-or-later relay behind a wall switch: in detached mode, the switch’s presses for the switch policy; otherwise, the relay as the light. One MQTT in node on <prefix>/#.

For any other device, the controller’s neutral commands and readings are the contract to map to; for a light, the room’s neutral light contract.

Check the result

Wire controller output 2 to a Debug node, then watch the adapter’s node status as well.

Read the outcome
What you seeWhat it means
Adapter status “waiting for the device”No device message has arrived yet. Check the MQTT in topics and the broker.
shelly cover statusThe cover’s last state and position.
zigbee2mqtt cover status as a position (such as 60%), an end state, or a motion with a positionReports are arriving and being read.
zigbee2mqtt cover status “online” / “offline”The last message was an availability report.
Controller result not-calibrated / position-unknownA shelly cover cannot provide a usable position. Calibrate it on the device.
Controller result unavailableThe device is offline. No command is sent; it is read again when it returns.
Controller error “observed cover reading has no position”A zigbee2mqtt cover reports no position: set the controller’s Cover to Open, close and stop only.
No command reaches the deviceCheck that the MQTT out node has no topic set and uses the same broker. For a shelly cover, check Enable MQTT Control; for a zigbee2mqtt cover, check the base topic and friendly name.

Importable examples are in the package’s examples folder (Import → Examples in the editor): Shelly cover.json wires a shelly cover, and Cover control.json wires a zigbee2mqtt cover. In each, injects stand in for the MQTT in nodes and a Debug node stands in for MQTT out. See also the README Covers section and the cover controller reference.
